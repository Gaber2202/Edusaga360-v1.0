# EduSaga 360 — Complete Schema Drift Map

Code's assumed schema vs. the real Supabase database (**68 tables, 840 columns**).
Generated by diffing every `.from()/.select()/.eq()/.order()/.match()/tenantQuery()`
reference in `backend/src` and `frontend/src` against `information_schema`, and
cross-checked against live Postgres error logs.

## Root cause (one sentence)

The app is a **Base44 export** whose code targets Base44's naming conventions
(`created_date`, naive-pluralized entity tables, `name`, `is_active`, `employee_id`),
but the live database was (re)built with Postgres conventions (`created_at`,
snake-plural tables, `name_en`/`name_ar`, `employee_number`). Any read that hits a
missing column/table returns a PostgREST error, which the UI surfaces as a generic
"failed to load" — the exact Executive Command Center symptom, reproduced across
much of the app.

---

## Category A — `created_date` must become `created_at` (SYSTEMIC, highest impact)

- No table in the real schema has `created_date`; **every** table uses `created_at`.
- **135** hard-crash `.order('created_date', …)` calls in the frontend → PostgREST
  400 → the page fails to load.
- **144** files reference `created_date` total (the non-`.order` ones are soft
  failures: `new Date(row.created_date)` silently yields `Invalid Date`).
- **Fix:** global rename `created_date` → `created_at` across `frontend/src`.

## Category D — Column drift on tables that DO exist

High-confidence (single-statement-bounded extraction, manually verified):

| Table | Code column | Real column / fix |
|---|---|---|
| `employees` | `employee_id` | `employee_number` (or `id`) |
| `employees` | `hire_date` | `join_date` |
| `employees` | `end_date` | `contract_end_date` |
| `employees` | `job_title` | `job_title_id` (FK → `job_titles`) |
| `employees` | `job_title_name` | join `job_titles(name_en,name_ar)` |
| `employees` | `department_name` | join `departments(name_en,name_ar)` |
| `employees` | `is_saudi` | derive from `nationality` (regex, per `payroll.ts`) |
| `employees` | `is_gosi_applicable` | derive from `nationality` |
| `employees` | `passport_expiry`, `visa_expiry` | no such columns (only `iqama_expiry`, `contract_end_date`) |
| `tenants` | `name` | `name_en` / `name_ar` |
| `tenants` | `email` | `admin_email` (or `billing_email`) |
| `tenants` | `address`, `address_ar`, `cr_number`, `vat_number`, `phone` | none exist (invoice/ZATCA header will be blank) |
| `chart_of_accounts` | `account_code` | `code` |
| `branches` | `is_active` (via `.match({is_active})`) | `status` / `is_main` |
| `fee_structures` | `name_en`, `name_ar` | `name` (single column) |
| `payment_plans` | `name_en`, `name_ar` | none — table has `plan_type`, no name |
| `fee_types` | `display_order` | none (has `category`, `code`, `is_recurring`) |
| `employee_attendance` | `is_excused`, `late_minutes` | none exist |
| `payslip_lines` | `total_deductions` | sum `other_deductions` + `loan_deduction` + `gosi_employee` |
| `audit_logs` | `timestamp` | `created_at` |

> **Note on an uncaught vector:** filters written as `.match({ is_active: true })`
> (object form, not `.eq('is_active', …)`) are NOT caught by the static scan but
> DO appear in the live logs (`branches.is_active`, `grades.is_active`,
> `sections.is_active`, `academic_years.is_active`, `fiscal_periods.is_active`).
> A `.match({...})` audit is needed in addition to this report.

## Suggested remediation order

1. **Category A** — one mechanical find/replace (`created_date`→`created_at`),
   unblocks the most pages for the least effort.
2. **Category D** — per-table column renames (bounded, ~10 tables).
3. **Category B** — fix the two table-name typos.
4. **Category C** — product decision per feature: build the table or delete the page.
